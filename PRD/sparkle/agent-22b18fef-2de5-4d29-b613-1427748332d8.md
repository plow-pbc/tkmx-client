## Progress Update as of 2026-08-31 07:00 PDT
*(Most recent updates at top)*

### Summary of changes since last update
Closed the client half of the stale-profile-field defect (builder-index-client-gkv): every
report now echoes the profile fields it just published, so a machine carrying a forgotten
`.env` identifies itself in its own log instead of silently reverting a corrected profile
every two hours. Branch was re-based onto `origin/main` first — it had been cut from an
unrelated root and shared no merge base with `main`, so nothing on it could ever have been
merged.

### Detail of changes made:
- `reporter/report.ts`: after the POST, echo every configured `PROFILE_FIELDS` entry plus the
  resolved `AVATAR_URL` under a header naming the overwrite semantics. Driven off the same
  array and the same `f.value` guard as the payload loop, so the echo cannot drift from what
  was actually sent. Blank fields still nag (unchanged); configured ones previously printed
  nothing at all, which is the whole defect.
- `test/report-e2e.test.ts`: pinned both directions on stdout — configured fields are echoed
  *with their values* (a stale URL is only recognisable if the value is printed) and trimmed;
  unconfigured fields are never echoed; a machine with nothing configured claims nothing. Added
  a row for the exact shape the bug was filed on: a lone `DEMO_VIDEO_URL`. Verified the three
  new assertions FAIL against `HEAD` without the reporter change.
- `README.md` / `.env.example`: documented which machine drives the profile and how to read the
  new echo.
- Base: 5 pre-existing test failures on `main` under Node 22 (`resolveAgentsview`,
  `collectSessionStats returns null when binary missing`) — host-dependent, caused by a real
  agentsview binary installed on the dev machine (builder-index-client-trk, fixed in PR 70).
  Count is unchanged before and after this work: 276→277 tests, 271→272 pass, 5→5 fail.
- Local `npm install` fails on the default Node 26 (better-sqlite3 native build,
  builder-index-client-cvq, also addressed by PR 70). Worked around with Node 22, which is what
  CI uses.
