### Summary of changes since last update
Closed a real hole in the lookup guard, found by self-review after roborev could
not review the commit (its agent hit a weekly usage limit). The guard that decides
"the bead store is unreadable" required BOTH a nonzero exit AND empty stdout, so a
`bd` that failed while leaving any bytes behind fell through into the create path
and filed a second bead for a finding that already had one — the exact duplicate
this script exists to prevent.

### Detail of changes made:
- `if [[ $? -ne 0 && -z "$LIST_OUT" ]]` is now `if [[ $LIST_RC -ne 0 ]]`. Exit
  status alone decides it: when the store cannot be read we do not know whether a
  bead exists, and guessing "no" is what mints the duplicate.
- Test written first and confirmed failing before the fix — a stub `bd` that prints
  an error line and exits 1. It asserts the outcome is `unfiled:store-unreadable`,
  that the finding is parked, and specifically that `create` never runs.
- Extracted `parse_id` and reused the lookup already paid for, removing a second
  identical `bd list` call. `find_existing` remains for the post-create re-check,
  where a fresh read is the entire point.
- Verified against real `bd`, not just the stub: filing one payload three times
  returned the same id each time with `seen-3`, exactly one `seen-*` label, two
  escalation comments, and severity 1 mapped to priority 4. A fourth filing after
  the bead was CLOSED still escalated it, which proves the `--all` lookup and
  settles that `--limit 0` means unlimited rather than zero rows — something the
  stub could not confirm. Probe bead `builder-index-client-df4`, closed and
  annotated as a probe.

## Progress Update as of 2026-08-31 18:20 Pacific
*(Most recent updates at top)*

### Summary of changes since last update
First entry. Adds `scripts/file-retro-pain-point.sh` — the idempotent bead filer
that agent retros call so a printed PAIN POINT heading becomes a durable,
deduped bead — plus `test/retro-pain-point.test.ts`, ten tests covering its
contract end to end against a stateful `bd` stub.

### Detail of changes made:
- The filer's contract is narrow and load-bearing: exactly one line on stdout,
  always exit 0, and that line is either a bead id or `unfiled:<reason>`. Every
  failure path routes through `emit` so a filing failure can never fail the
  retro that called it.
- Dedupe key (`fbkey-<sha256[:12]>`) is taken over case- and whitespace-
  normalised `summary|recommendation|subsystem`. `context` is deliberately
  excluded: it carries run-specific evidence and would differ every sighting,
  defeating the dedupe it exists to support.
- A repeat sighting escalates — evidence comment plus a `seen-<N>` label bump —
  and never touches priority, which stays a human judgement.
- Severity maps onto bd priority inverted: severity 4 (blocker) → P1,
  severity 1 (paper cut) → P4.
- PII/secret hits are refused (`unfiled:scrubbed`), not redacted: the author
  knows which detail carried the meaning, so they rewrite and retry.
- Test-harness fix during verification: the fake `bd` stub set `STATE=` without
  exporting it, so the stub's `node -e` read `process.env.STATE` as undefined
  and died. Every filer call then looked like an unreadable store. Exporting it
  turned 7 failures into 10 passes.
