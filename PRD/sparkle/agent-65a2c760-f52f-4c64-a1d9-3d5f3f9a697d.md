## Progress Update as of 2026-08-31 18:20 Pacific

### Summary of changes since last update
First entry. Adds `scripts/file-retro-pain-point.sh` — the idempotent bead filer
that agent retros call so a printed PAIN POINT heading becomes a durable,
deduped bead — plus `test/retro-pain-point.test.ts`, ten tests covering its

### Detail of changes made:
- The filer's contract is narrow and load-bearing: exactly one line on stdout,
  always exit 0, and that line is either a bead id or `unfiled:<reason>`. Every
  failure path routes through `emit` so a filing failure can never fail the
  retro that called it.
- Dedupe key (`fbkey-<sha256[:12]>`) is taken over case- and whitespace-
  normalised `summary|recommendation|subsystem`. `context` is deliberately
  excluded: it carries run-specific evidence and would differ every sighting,
  defeating the dedupe it exists to support.
- A repeat sighting escalates — evidence comment plus a `seen-<N>` label bump —
  and never touches priority, which stays a human judgement.
- Severity maps onto bd priority inverted: severity 4 (blocker) → P1,
  severity 1 (paper cut) → P4.
- PII/secret hits are refused (`unfiled:scrubbed`), not redacted: the author
  knows which detail carried the meaning, so they rewrite and retry.
- Test-harness fix during verification: the fake `bd` stub set `STATE=` without
  exporting it, so the stub's `node -e` read `process.env.STATE` as undefined
  and died. Every filer call then looked like an unreadable store. Exporting it
  turned 7 failures into 10 passes.
