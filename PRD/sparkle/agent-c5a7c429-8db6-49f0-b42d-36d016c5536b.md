### Summary of changes since last update
First entry for this branch. Added `reporter/duplicate-prs.ts`, a tool that finds
open pull requests doing the same job by clustering them on overlapping file
sets rather than on title text, plus 15 tests and an `npm run duplicate-prs`
script. This is the automated half of builder-index-client-9fn.

### Detail of changes made:
- The branch began life rooted at the orphan `bd init` commit `aaf4d44`, which
  shares no history with `origin/main` — the defect recorded in
  builder-index-client-fy6, which names this branch in its census. The commit
  was a strict duplicate of what PR #69 already carries, so per that bead's
  stated disposition it was DROPPED, not relocated: the branch was reset onto
  `origin/main` (the orphan is preserved as tag `orphan-backup-c5a7c429`).
  `git merge-base HEAD origin/main` now resolves.
- `clusterByFileOverlap` scores a pair of pull requests as
  `|A n B| / min(|A|, |B|)`. The `min` denominator is the point: the common
  shape of duplicated work here is a small branch wholly contained in a large
  one, and a union denominator rates that pair near zero and misses it.
- Linkage is transitive (union-find, single linkage). A pairwise sweep that
  never merges groups splits one job across several clusters and understates
  the duplication.
- Transitivity needs a guard, which a live run found rather than a test: files
  touched by a strict majority of open pull requests are dropped before
  scoring. `.gitignore` appeared in 13 of 21 open pull requests and, through
  that one file, welded Ask-a-Builder (#74), a worktree-marker fix (#84) and a
  bead filer (#90) onto the beads-scaffolding cluster. The majority bar is
  deliberately high; a quarter-of-the-board rule eats the real signal on a
  small board, where three of five pull requests sharing files IS the
  duplication.
- Live output on the current board: 9 open pull requests (#69, #80, #81, #91,
  #92, #93, #94, #95, #96) are one job, sharing 8 files including `AGENTS.md`,
  `CLAUDE.md` and `.beads/metadata.json`; a second cluster of 3 (#79, #82, #89)
  shares `.env.example`, `README.md` and `test/report-e2e.test.ts`.

### Potential concerns to address:
- The tool reports; it does not act. Nine redundant pull requests are still
  open and were deliberately not closed here — they belong to other agents and
  closing them is a human judgement call.
- The report alone does not break the loop that creates duplicates. While a
  fix sits unmerged its bead stays `open`, so `bd ready` keeps advertising it
  as unclaimed and the next fan-out mints another twin. Cross-referencing open
  pull request branches into `bd ready` is the durable fix; filed as the second
  remediation on builder-index-client-9fn.
