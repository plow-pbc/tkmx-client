### Summary of changes since last update
Third roborev round found that the hub-file rule went SILENT on the exact

cutoff entirely and replaced it with a shared-file requirement. Module tests

### Detail of changes made:
- THE DEFECT, reproduced before fixing: ten pull requests doing one job on a
  fourteen-pull-request board. Their shared files sit in 10 of 14 branches,
  over any frequency cutoff, so every one of those paths was discarded as a hub
  and the group dissolved. A scripted repro printed "clusters found: 0" — the
  beads-scaffolding incident, invisible. It survived on the live 21-branch
  board only by luck of where the cutoff happened to land.
- ROOT CAUSE: frequency cannot separate "many branches touch this file
  incidentally" from "many branches touch it BECAUSE they are the same job".
  The counts are identical. Raising the fraction re-breaks the .gitignore case
  and lowering it eats small boards, so the knob was exhausted, not mistuned.
- THE REPLACEMENT: no global filtering at all. A pair links only if it shares
  at least two files AND clears the overlap threshold. What actually separated
  false links from real ones on the live board was never frequency — the
  unrelated pull requests shared exactly ONE file with the cluster while every
  genuine member shared eight.
- A first attempt bent the requirement down for small branches ("a one-file
  branch cannot share two"), and the live board rejected it: a one-file pull
  request touching only .gitignore scored 1.00 against everything else that
  touched it and became the BRIDGE that re-welded the same three unrelated
  features on. Measuring beat reasoning here — the rule looked obviously safe.
  The requirement now bends only for two branches with IDENTICAL file sets,
  which cannot bridge anything they are not already identical to.
- Live board before/after on the same data: 13 pull requests in a cluster of 13
  (wrong, includes Ask-a-Builder, a worktree fix, a bead filer) -> 10 in a
  cluster of 10. #84 stays, correctly: it shares .gitignore AND
  test/gitignore.test.ts with #69, which is a real collision, not a coincidence.

## Progress Update as of 2026-09-01 13:05 Pacific
*(Most recent updates at top)*

### Summary of changes since last update
First entry for this branch. Added `reporter/duplicate-prs.ts`, a tool that finds
open pull requests doing the same job by clustering them on overlapping file
sets rather than on title text, plus 15 tests and an `npm run duplicate-prs`
script. This is the automated half of builder-index-client-9fn.

### Detail of changes made:
- The branch began life rooted at the orphan `bd init` commit `aaf4d44`, which
  shares no history with `origin/main` — the defect recorded in
  builder-index-client-fy6, which names this branch in its census. The commit
  was a strict duplicate of what PR #69 already carries, so per that bead's
  stated disposition it was DROPPED, not relocated: the branch was reset onto
  `origin/main` (the orphan is preserved as tag `orphan-backup-c5a7c429`).
  `git merge-base HEAD origin/main` now resolves.
- `clusterByFileOverlap` scores a pair of pull requests as
  `|A n B| / min(|A|, |B|)`. The `min` denominator is the point: the common
  shape of duplicated work here is a small branch wholly contained in a large
  one, and a union denominator rates that pair near zero and misses it.
- Linkage is transitive (union-find, single linkage). A pairwise sweep that
  never merges groups splits one job across several clusters and understates
  the duplication.
- Transitivity needs a guard, which a live run found rather than a test: files
  touched by a strict majority of open pull requests are dropped before
  scoring. `.gitignore` appeared in 13 of 21 open pull requests and, through
  that one file, welded Ask-a-Builder (#74), a worktree-marker fix (#84) and a
  bead filer (#90) onto the beads-scaffolding cluster. The majority bar is
  deliberately high; a quarter-of-the-board rule eats the real signal on a
  small board, where three of five pull requests sharing files IS the
  duplication.
- Live output on the current board: 9 open pull requests (#69, #80, #81, #91,
  #92, #93, #94, #95, #96) are one job, sharing 8 files including `AGENTS.md`,
  `CLAUDE.md` and `.beads/metadata.json`; a second cluster of 3 (#79, #82, #89)
  shares `.env.example`, `README.md` and `test/report-e2e.test.ts`.
